    Lanzamiento excepciones: raise

    1. ¿Para qué sirve?

    Python puede generar una excepción automáticamente cuando se produce un error durante la ejecución del programa. Por ejemplo:

    numero = int("hola")  # Genera ValueError

    En otras ocasiones, es nuestro programa el que debe detectar una situación incorrecta. Aunque la instrucción sea válida desde el punto de vista del lenguaje, quizá no lo sea para nuestra aplicación.

    Para lanzar una excepción de forma explícita utilizamos raise:

    raise TipoExcepcion("Mensaje descriptivo del error")

    Por ejemplo:

    edad = -5

if edad < 0:
    raise ValueError("La edad no puede ser negativa")

    Python permite almacenar un número negativo en una variable; somos nosotros quienes decidimos que ese valor no es aceptable como edad.

    ¿Qué ocurre al ejecutar raise?

    1. Se lanza la excepción indicada.
    2. Se interrumpe la ejecución normal del bloque donde se encuentra.
    3. Python busca un manejador except que pueda tratarla.
    4. Si no lo encuentra, la excepción se propaga hasta otro nivel de llamada; si nadie la captura, termina mostrando un traceback.

    2. Ejemplo uso

    Estamos desarrollando una pequeña aplicación de administración de sistemas que gestiona sensores. Cada sensor tiene un identificador y un estado: "up" (activo) o "down" (inactivo).

    Partimos de esta lista de diccionarios:

    sensores_pasillo = [
    {"id": 100, "estado": "up"},
    {"id": 200, "estado": "down"},
    {"id": 300, "estado": "down"},
]

    Queremos programar una función modifica_estado(sensores, id_sensor, nuevo_estado) que cambie el estado de un sensor. Antes de modificar nada, la función debe comprobar que:

    1. El identificador es positivo.
    2. El estado solicitado es "up" o "down".
    3. Existe un sensor con ese identificador.

    2.1. Implementación de la función

    def modifica_estado(sensores, id_sensor, nuevo_estado):
    # Validamos el identificador.
    if id_sensor <= 0:
        raise ValueError("El identificador debe ser positivo")

    # Validamos el estado solicitado.
    if nuevo_estado not in ("up", "down"):
        raise ValueError("El estado debe ser 'up' o 'down'")

    # Buscamos el sensor y, si existe, modificamos su estado.
    for sensor in sensores:
        if sensor["id"] == id_sensor:
            sensor["estado"] = nuevo_estado
            return

    # Solo llegamos aquí si no encontramos el sensor.
    raise ValueError(f"No existe ningún sensor con id {id_sensor}")

    Tres situaciones, tres lanzamientos

    • id_sensor <= 0: identificador no válido.
    • nuevo_estado not in ("up", "down"): estado no permitido.
    • Fin del bucle sin encontrar el identificador: sensor inexistente.

    ¿Por qué utilizamos ValueError? Porque, en los dos primeros casos, el valor recibido no es válido para la operación, aunque su tipo sea adecuado. En este ejemplo introductorio también la usamos para indicar que el identificador no corresponde a ningún sensor.

    Observa el return que aparece dentro del bucle. Si se encuentra el sensor, se cambia su estado y la función termina. Por tanto, el último raise solo se ejecuta cuando se ha recorrido toda la lista sin encontrarlo.

    2.2. Captura excepciones

    La función comprueba los datos y, si detecta un problema, lanza una excepción. El programa principal decide cómo comunicarlo al usuario. Este es el ejemplo completo, listo para ejecutarse:

    sensores_pasillo = [
    {"id": 100, "estado": "up"},
    {"id": 200, "estado": "down"},
    {"id": 300, "estado": "down"},
]


def modifica_estado(sensores, id_sensor, nuevo_estado):
    if id_sensor <= 0:
        raise ValueError("El identificador debe ser positivo")

    if nuevo_estado not in ("up", "down"):
        raise ValueError("El estado debe ser 'up' o 'down'")

    for sensor in sensores:
        if sensor["id"] == id_sensor:
            sensor["estado"] = nuevo_estado
            return

    raise ValueError(f"No existe ningún sensor con id {id_sensor}")


try:
    id_sensor = int(input("Id sensor (entero positivo): "))
    nuevo_estado = input("Nuevo estado [up|down]: ").strip().lower()

    modifica_estado(sensores_pasillo, id_sensor, nuevo_estado)

except ValueError as error:
    print(f"Error: {error}")

else:
    print("Estado modificado correctamente")
    print(sensores_pasillo)

    El bloque try ejecuta la lectura y la modificación. Si en cualquiera de esas instrucciones aparece un ValueError, el programa salta al bloque except. La variable error contiene el objeto excepción, cuyo mensaje puede mostrarse con print().

    El bloque else solo se ejecuta si ninguna instrucción del try ha producido una excepción.

    Excepciones automáticas y explícitas en el mismo except

    La llamada int(input(...)) también puede producir un ValueError si el usuario escribe, por ejemplo, abc. Por tanto, el mismo except ValueError captura errores de conversión generados por Python y errores de validación lanzados por nuestra función con raise.

    2.3. Pruebas

    Caso 1. Operación correcta

    Id sensor (entero positivo): 200
Nuevo estado [up|down]: up
Estado modificado correctamente
[{'id': 100, 'estado': 'up'}, {'id': 200, 'estado': 'up'}, {'id': 300, 'estado': 'down'}]

    Caso 2. Identificador negativo

    Id sensor (entero positivo): -10
Nuevo estado [up|down]: up
Error: El identificador debe ser positivo

    Caso 3. Estado no permitido

    Id sensor (entero positivo): 100
Nuevo estado [up|down]: error
Error: El estado debe ser 'up' o 'down'

    Caso 4. Sensor inexistente

    Id sensor (entero positivo): 999
Nuevo estado [up|down]: down
Error: No existe ningún sensor con id 999

    Caso 5. El identificador no es un número

    Id sensor (entero positivo): abc
Error: invalid literal for int() with base 10: 'abc'

    3. Propagación de las excepciones

    Cuando una función ejecuta un raise, no tiene por qué capturar esa misma excepción: puede dejar que se propague hasta el código que llamó a la función.

    En nuestro ejemplo, si intentamos modificar un sensor con el estado "error", ocurre lo siguiente:

    1. El programa principal llama a modifica_estado(...) desde el try.
    2. La función detecta que el nuevo estado no está permitido.
    3. La función ejecuta raise ValueError(...) y se interrumpe su ejecución normal.
    4. La excepción vuelve al código que hizo la llamada.
    5. El bloque except ValueError as error captura la excepción y muestra el mensaje.

    Podemos comprobar que las instrucciones posteriores a un raise no se ejecutan:

    def ejemplo():
    print("Inicio de la función")
    raise ValueError("Se ha producido un error")
    print("Fin de la función")  # No se ejecutará.


try:
    ejemplo()
except ValueError as error:
    print(f"Excepción capturada: {error}")

    Salida:

    Inicio de la función
Excepción capturada: Se ha producido un error

    Importante

    raise no significa simplemente «mostrar un mensaje». Su efecto es lanzar una excepción y alterar el flujo de ejecución. Si nadie captura la excepción, el programa muestra un traceback y termina.

    4. Errores frecuentes al trabajar con excepciones

    5. Resumen

    • raise lanza una excepción explícitamente cuando el programa detecta un problema.
    • Una función puede detectar el problema y dejar que otro bloque de código lo gestione.
    • Cuando se ejecuta raise, se interrumpe el flujo normal y la excepción puede propagarse hasta un except.
    • return sirve para finalizar una función y, opcionalmente, devolver un resultado; raise comunica una situación excepcional.
    • Conviene utilizar tipos de excepción apropiados, mensajes descriptivos y bloques except concretos.

    Idea clave

    Una función puede devolver un resultado cuando todo va bien y lanzar una excepción cuando no puede completar la operación.
