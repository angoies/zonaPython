    Introducción a Python - Linters

    1. Introducción

    Hay determinados problemas en el código que pueden detectarse antes de ejecutar el programa:

    • errores de sintaxis
    • nombres que no existen
    • módulos importados pero no utilizados
    • variables creadas pero no usadas
    • código poco legible o difícil de mantener
    • uso de malas prácticas
    • estilos de código inconsistentes.

    Las herramientas que analizan el código buscando este tipo de problemas se denominan linters. En Python existen distintas herramientas, entre ellas:

    • Flake8
    • Pylint
    • Pyflakes
    • Ruff
    • ...

    En este tema utilizaremos principalmente Flake8.

    ¿Qué hace un linter?

    Un linter realiza análisis estático del código: examina el código fuente sin necesidad de ejecutarlo.

    Un linter puede detectar muchos problemas, pero no puede garantizar que el programa funcione correctamente. Para comprobar el comportamiento del programa necesitamos técnicas como el testing.

    1.1. ¿Qué es Flake8?

    Flake8 reúne comprobaciones procedentes de herramientas como:

    • Pyflakes, para detectar determinados errores en el código;
    • pycodestyle, para comprobar convenciones de estilo;
    • McCabe, para medir complejidad ciclomática.

    Entre otras cosas puede detectar imports no utilizados, nombres no definidos, problemas de espaciado, líneas demasiado largas y funciones excesivamente complejas.

    A continuación:

    1. partiremos de un fichero con errores: test_linters_inicial.py;
    2. crearemos un entorno virtual;
    3. instalaremos flake8;
    4. ejecutaremos el linter desde la línea de comandos;
    5. veremos su integración con Visual Studio Code;
    6. aprenderemos lo básico sobre selección, exclusión y configuración de reglas.

    2. Instalación

    Crear un entorno virtual:

    clases@d13:~/calidad$ python3 -m venv venv
clases@d13:~/calidad$ source venv/bin/activate
(venv) clases@d13:~/calidad$

    Instalar Flake8:

    (venv) clases@d13:~/calidad$ pip install flake8

    Comprobar la versión instalada:

    (venv) clases@d13:~/calidad$ flake8 --version

    3. Ejecución desde la línea de comandos

    Se indica a flake8 el fichero que quiere revisar:

    (venv) clases@d13:~/calidad$ flake8 test_linters_inicial.py
test_linters_inicial.py:8:1: F401 'io' imported but unused
test_linters_inicial.py:10:1: F403 'from math import *' used; unable to detect undefined names
test_linters_inicial.py:14:1: E303 too many blank lines (3)
test_linters_inicial.py:28:5: F841 local variable 'some_global_var' is assigned to but never used
test_linters_inicial.py:30:15: E225 missing whitespace around operator
test_linters_inicial.py:41:80: E501 line too long (80 > 79 characters)
test_linters_inicial.py:51:10: E711 comparison to None should be 'if cond is not None:'
test_linters_inicial.py:55:25: E703 statement ends with a semicolon
test_linters_inicial.py:63:23: E275 missing whitespace after keyword
test_linters_inicial.py:63:24: E201 whitespace after '('
...

    Cada mensaje sigue una estructura similar:

    fichero:línea:columna: código descripción

    Por ejemplo:

    test_linters_inicial.py:28:5: F841 local variable 'some_global_var' is assigned to but never used

    indica:

    • fichero: test_linters_inicial.py;
    • línea: 28;
    • columna: 5;
    • código: F841;
    • problema: se asigna un valor a una variable local que después no se utiliza.

    El programa puede seguir funcionando

    Muchos avisos de un linter no provocan necesariamente un error durante la ejecución.

    Una variable no utilizada, por ejemplo, no impide que el programa funcione, pero puede indicar código innecesario o un olvido del programador.

    3.1. Analizar un directorio completo

    Podemos analizar el directorio actual o una carpeta concreta 

    $ flake8 .
$ flake8 src/

    4. Corregir los avisos

    Un linter señala problemas, pero normalmente es el programador quien decide cómo corregirlos.

    No corregir sin pensar

    El objetivo no es conseguir que desaparezcan todos los mensajes a cualquier precio.

    Hay que comprender qué está señalando cada aviso y decidir cuál es la corrección adecuada.

    5. Flake8 en Visual Studio Code

    Visual Studio Code dispone actualmente de una extensión Flake8 publicada por Microsoft.

    Una vez instalada:

    • los problemas aparecen directamente en el editor;
    • también aparecen en el panel Problemas;
    • el análisis puede ejecutarse automáticamente al trabajar con archivos Python.

    Si se mantiene la figura existente:

    ![](figuras/linter-01.png)

    Configuración antigua de VS Code

    En versiones antiguas se elegía el linter mediante Python: Select Linter.

    Ese procedimiento está obsoleto. Actualmente Flake8 se integra mediante una extensión independiente.

    La extensión actual incluye su propia versión de Flake8, aunque también puede configurarse para usar una instalación del entorno del proyecto.

    Para este curso es suficiente recordar:

    1. instalar Flake8 en el entorno virtual para usarlo desde terminal;
    2. instalar la extensión Flake8 de Microsoft para usarlo desde VS Code.

    6. Opciones

    6.1. Seleccionar reglas: --select

    Puede revisar solo determinados códigos:

    flake8 --select E225,E501 test_linters_inicial.py

    O seleccionar grupos:

    flake8 --select E,W .

    6.2. Ignorar reglas: --ignore

    Podemos indicar reglas que no queremos mostrar:

    flake8 --ignore E501,E303 test_linters_inicial.py

    No abusar de ignore

    Ignorar una regla puede estar justificado, pero no debería utilizarse simplemente para ocultar problemas sin revisarlos.

    6.3. Ignorar una línea # noqa

    Podemos ignorar un aviso en una línea concreta:

    import modulo_no_usado  # noqa

    O indicar el código:

    import modulo_no_usado  # noqa: F401

    noqa no sustituye a corregir el código

    Debe utilizarse solo cuando exista una razón clara para mantener esa línea.

    flake8 ejercicio.py

    Crea .flake8:

    Después:

    flake8 .

    7.5. Ejercicio 5. Linting frente a testing

    Considera:

    def calcula_doble(numero):
    return numero * 3
    1. Ejecuta Flake8.
    2. Comprueba si detecta algún problema.
    3. Escribe un test que espere que calcula_doble(5) devuelva 10.
    4. Explica por qué linter y test producen resultados diferentes.

    8. Soluciones orientativas

    8.1. Solución del ejercicio 2

    nombre = "servidor01"
puerto = 22

print(nombre)

if puerto == 22:
    print("Servicio SSH")

    Los imports se han eliminado porque no se utilizaban y se han añadido espacios alrededor de los operadores.

    8.2. Solución del ejercicio 5

    Flake8 puede no mostrar ningún problema en:

    def calcula_doble(numero):
    return numero * 3

    Sin embargo:

    def test_calcula_doble():
    assert calcula_doble(5) == 10

    fallará porque 5 * 3 vale 15.

    Esto ilustra que el linter no comprueba si la lógica de negocio es correcta.

    2. Anexo: Pylint

    El objetivo de este tema es conocer los linters y aprender su uso básico. Con Flake8 es suficiente para ello.

    Como alternativa podemos probar Pylint.

    Instalación:

    (venv) clases@d13:~/calidad$ pip install pylint

    Ejecución:

    (venv) clases@d13:~/calidad$ pylint test_linters_inicial.py

    Puede mostrar mensajes como:

    W0301: Unnecessary semicolon (unnecessary-semicolon)
C0325: Unnecessary parens after 'return' keyword (superfluous-parens)
C0304: Final newline missing (missing-final-newline)
W0622: Redefining built-in 'pow' (redefined-builtin)
W0401: Wildcard import math (wildcard-import)

    Pylint utiliza su propio conjunto de códigos y mensajes y suele mostrar también una valoración global.

    No comparar únicamente la puntuación

    Una puntuación baja de Pylint no significa necesariamente que el programa no funcione.

    Para ampliar información:

    • https://pylint.readthedocs.io/

    10. Anexos

    10.1. Linter, formatter y testing

    Conviene distinguir tres tipos de herramientas:

    Herramienta Objetivo
    Linter Detectar problemas, malas prácticas y errores de estilo
    Formatter Modificar automáticamente el formato del código
    Testing Comprobar que el programa produce los resultados esperados

    Por ejemplo:

    • flake8 es principalmente un linter;
    • black es un formatter;
    • pytest permite realizar tests.

    Estas herramientas se complementan entre sí.

    10.2. Linting y testing

    El linter y los tests detectan problemas diferentes.

    def suma(a, b):
    return a - b

    Este código puede pasar Flake8 perfectamente, aunque contiene un error lógico.

    Un test podría detectarlo:

    def test_suma():
    assert suma(2, 3) == 5

    Por tanto:

    linting != testing

    Ambas técnicas son complementarias.

    10.3. Algunos códigos habituales

    • F401 - Import no utilizado 
      import os

    Si posteriormente no utilizamos os, Flake8 puede mostrar:

    F401 'os' imported but unused
    • F841 - Variable local asignada pero no utilizada
    def ejemplo():
    resultado = 10
    print("Fin")

    Si resultado nunca se utiliza:

    F841 local variable 'resultado' is assigned to but never used
    • E225 - Falta espacio alrededor de un operador

    No recomendado:

    total=precio*cantidad

    Recomendado:

    total = precio * cantidad
    • E501 - Línea demasiado larga

    Podemos dividir expresiones largas utilizando paréntesis:

    mensaje = (
    "Este texto se ha dividido "
    "en varias líneas del código."
)
    • E711 - Comparación con None

    No recomendado:

    if resultado == None:

    Preferible:

    if resultado is None:
    • F403 - Importación con *

    No recomendado:

    from math import *

    Preferible:

    import math

    o:

    from math import sqrt

    10.4. Anexo: Configuración del proyecto

    Flake8 admite configuración en:

    • .flake8
    • setup.cfg
    • tox.ini

    La configuración se coloca en una sección:

    [flake8]

    Por ejemplo:

    [flake8]
ignore = E501,E303
exclude = .git,__pycache__,venv,build,dist
max-complexity = 10

    Después basta ejecutar:

    flake8 .
    • exclude permite excluir rutas:
    exclude = .git,__pycache__,venv,build,dist
    • Longitud máxima de las líneas
    [flake8]
max-line-length = 100
    • Complejidad ciclomática: cuanto más complicada sea la lógica de una función, más difícil puede resultar comprenderla, probarla y mantenerla
    max-complexity = 10

    10.5. Anexo: Prioridad de la configuración

    De forma simplificada:

    1. las opciones de línea de comandos tienen prioridad;
    2. después se usa la configuración del proyecto;
    3. finalmente se aplican los valores por defecto.
