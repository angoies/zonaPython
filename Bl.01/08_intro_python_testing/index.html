    Introducción a Python - Introducción al testing

    El testing consiste en comprobar de forma automática que nuestro programa se comporta como esperamos.

    En lugar de ejecutar el programa manualmente muchas veces y comprobar cada resultado a mano, podemos escribir pruebas que:

    1. ejecuten una función con unos datos determinados;
    2. comparen el resultado obtenido con el esperado;
    3. indiquen si la prueba ha sido correcta o ha fallado.

    En este tema utilizaremos principalmente pytest, aunque al final se incluye una breve introducción a unittest, que forma parte de la biblioteca estándar de Python.

    1. Módulo pytest

    pytest es un framework de pruebas para Python que permite escribir y ejecutar tests de forma sencilla y con poco código repetitivo.

    1.1. Instalación de pytest

    Es recomendable trabajar dentro de un entorno virtual para instalar pytest sin modificar los paquetes globales del sistema.

    clases@ssd:~/testing$ python3 -m venv venv
clases@ssd:~/testing$ source venv/bin/activate
(venv) clases@ssd:~/testing$

    Instalamos y verificamos:

    (venv) clases@ssd:~/testing$ pip install pytest
(venv) clases@ssd:~/testing$ pytest --version
pytest 9.1.1

    Entorno virtual

    Cuando está activado suele aparecer (venv) al comienzo del prompt.

    Para salir del entorno virtual:

    deactivate

    1.2. Código que vamos a probar

    Supongamos que tenemos este fichero:

    # File: seguridad.py

def comprueba_clave(login, password):
    valida = True

    claves_prohibidas = {
        "123456789012",
        "password12345",
        "administrador2026"
    }

    if len(password) < 10:
        valida = False
    elif password in claves_prohibidas:
        valida = False
    elif login in password:
        valida = False

    return valida

    La función devuelve True si la contraseña se considera válida y False en caso contrario.

    Las reglas implementadas son:

    • la contraseña debe tener al menos 10 caracteres;
    • no puede estar en el conjunto de claves prohibidas;
    • no puede contener el login del usuario.

    1.3. Fichero de test

    Para que pytest descubra automáticamente las pruebas:

    • los archivos suelen comenzar por test_;
    • las funciones de prueba deben comenzar por test_;
    • utilizamos assert para comparar el resultado obtenido con el esperado.
    # File: test_seguridad.py

import pytest
from seguridad import comprueba_clave


def test_clave_valida():
    """Clave válida."""
    assert comprueba_clave(
        "usuario123",
        "ClaveMuySegura2026!"
    ) is True


def test_clave_corta_menos_de_10_caracteres():
    """Clave con menos de 10 caracteres."""
    assert comprueba_clave(
        "usuario",
        "12345679"
    ) is False

    1.4. La instrucción assert

    La forma general es:

    assert resultado_obtenido == resultado_esperado

    Si la expresión es verdadera, la prueba pasa. Si es falsa, falla.

    Por ejemplo:

    assert comprueba_clave("usuario", "12345679") is False

    significa:

    Espero que esta llamada devuelva False.

    Para valores booleanos resulta habitual escribir:

    is True

    o:

    is False

    1.5. Ejecución

    Podemos ejecutar todos los tests descubiertos por pytest:

    pytest

    O un fichero concreto:

    pytest test_seguridad.py

    Con -v obtenemos más detalle:

    pytest -v

    Una ejecución correcta podría mostrar:

    collected 2 items

test_seguridad.py ..                                   [100%]

2 passed

    Cada punto representa una prueba superada.

    2. Diseñar buenos casos de prueba

    No basta con comprobar un único caso. Conviene pensar en varios tipos de pruebas.

    2.1. Casos válidos

    Entradas que deberían aceptarse:

    assert comprueba_clave(
    "juan",
    "ClaveSegura2026"
) is True

    2.2. Casos inválidos

    Entradas que deberían rechazarse:

    assert comprueba_clave(
    "admin",
    "123456789"
) is False

    2.3. Casos límite

    Son especialmente importantes. Si la condición es:

    if len(password) < 10:

    conviene probar:

    • 9 caracteres;
    • exactamente 10;
    • 11 caracteres.

    Prueba los límites

    Cuando una condición utiliza <, <=, > o >=, prueba valores justo por debajo, en el límite y justo por encima.

    3. Conjuntos de datos de prueba

    Podemos guardar varios casos en una lista de tuplas:

    dataset_pruebas = [
    ("juan_perez", "ContrasenaValida123", True),
    ("admin_sys", "SistemasOperativos2026", True),
    ("admin", "", False),
    ("admin", "123456789", False),
]

    Y recorrerlos:

    def test_comprueba_clave_con_bucle():
    for login, password, esperado in dataset_pruebas:
        resultado_real = comprueba_clave(login, password)

        assert resultado_real == esperado, (
            f"Fallo -> login='{login}', "
            f"password='{password}'"
        )

    3.1. Mensajes en assert

    Podemos añadir un mensaje en assert que solo se mostrará si la prueba falla.

    assert resultado == esperado, "Mensaje si falla"

    3.2. Limitación del bucle

    Para pytest, toda la función sigue siendo un único test. Si un assert falla, el bucle no continúa con el resto de casos. Por eso resulta muy útil la parametrización.

    4. Pruebas parametrizadas

    pytest permite ejecutar la misma función varias veces con diferentes datos:

    @pytest.mark.parametrize(
    "login, password, resultado_esperado",
    [
        ("juan_perez", "ContrasenaValida123", True),
        ("admin_sys", "SistemasOperativos2026", True),
        ("admin", "1234", False),
        ("admin", "password", False),
    ],
)
def test_comprueba_clave_parametrizado(
    login,
    password,
    resultado_esperado
):
    assert(comprueba_clave(login, password)== resultado_esperado)

    Cada tupla se convierte en un caso de prueba independiente. Ventajas de pruebas paramrtrizadas respecto al bucle:

    • si uno falla, los demás siguen ejecutándose;
    • pytest indica qué combinación ha fallado;
    • evitamos repetir muchas funciones similares.

    5. Detectar un error real

    Probemos:

    assert comprueba_clave(
    "administrador2026",
    "Administrador2026"
) is False

    Esperamos que sea inválida porque la contraseña contiene el login.

    Sin embargo, la función original utiliza:

    elif login in password:

    y esta comparación distingue mayúsculas y minúsculas. Por tanto el login administrador2026 no coincide con Administrador2026

    El test nos ha permitido descubrir un caso que la implementación original no contemplaba.

    6. Corregir la comparación

    Podemos normalizar ambos textos antes de compararlos:

    def comprueba_clave(login, password):
    valida = True

    claves_prohibidas = {
        "123456789012",
        "password12345",
        "administrador2026"
    }

    login_normalizado = login.lower()
    password_normalizada = password.lower()

    if len(password) < 10:
        valida = False
    elif password_normalizada in claves_prohibidas:
        valida = False
    elif login_normalizado in password_normalizada:
        valida = False

    return valida

    Normalizar antes de comparar

    Convertir ambos textos a minúsculas permite hacer una comparación que no dependa de mayúsculas y minúsculas.

    7. Ejercicios

    1. Amplía los tests para comprobar todos los requisitos:

    2. longitud mínima;

    3. claves prohibidas;

    4. presencia del login en la contraseña.

    5. Añade el caso de login administrador2026 y password Administrador2026. Comprueba que la primera versión de la función no se comporta como esperamos.

    6. Modifica comprueba_clave() para ignorar diferencias entre mayúsculas y minúsculas.

    7. Añade casos combinando mayúsculas y minúsculas.

    8. Añade tests para contraseñas de:

    9. 9 caracteres;

    10. 10 caracteres;

    11. 11 caracteres.

    12. Convierte un test basado en un bucle en una prueba parametrizada.

    8. Anexo: unittest

    Python incluye de serie el módulo unittest, por lo que no es necesario instalarlo.

    Las pruebas suelen escribirse como métodos de una clase que hereda de unittest.TestCase:

    import unittest

from seguridad import comprueba_clave


class TestCompruebaClave(unittest.TestCase):

    def test_clave_valida(self):
        self.assertTrue(
            comprueba_clave(
                "usuario123",
                "ClaveMuySegura2026!"
            )
        )

    def test_clave_corta(self):
        self.assertFalse(
            comprueba_clave(
                "usuario",
                "12345679"
            )
        )


if __name__ == "__main__":
    unittest.main()

    8.1. Métodos habituales

    self.assertTrue(valor)
self.assertFalse(valor)
self.assertEqual(valor1, valor2)
self.assertNotEqual(valor1, valor2)

    8.2. Conjuntos de datos con subTest

    import unittest

from seguridad import comprueba_clave


class TestCompruebaClave(unittest.TestCase):

    def test_varios_casos(self):
        dataset = [
            (
                "juan_perez",
                "ContrasenaValida123",
                True
            ),
            ("admin", "1234", False),
            ("usuario", "password12345", False),
        ]

        for login, password, esperado in dataset:
            with self.subTest(
                login=login,
                password=password
            ):
                resultado = comprueba_clave(
                    login,
                    password
                )
                self.assertEqual(resultado, esperado)


if __name__ == "__main__":
    unittest.main()

    subTest() permite distinguir mejor los diferentes casos de un mismo bucle de prueba: permite saber qué subcaso falló y di un subtest falla, los siguientes también se ejecutan. Es el equivalente práctico más cercano en unittest a las pruebas parametrizadas de pytest, aunque internamente no funcionan exactamente igual.

    8.3. pytest o unittest

    En este curso utilizaremos principalmente pytest porque permite escribir pruebas muy sencillas y facilita especialmente la parametrización. unittest también es importante porque:

    • viene incluido con Python;
    • se utiliza en muchos proyectos;
    • no necesita paquetes adicionales.

    Tenga en cuenta que con unittest + subTest() el resultado suele ser **menos detallado que con `pytest.mark.

    subTest() permite ejecutar varios casos dentro de un mismo método de unittest y saber cuál ha fallado, pero pytest.mark.parametrize convierte cada conjunto de datos en un caso de prueba independiente y ofrece una salida más detallada.

    unittest + subTest() pytest.mark.parametrize
    Dataset con 3 casos 1 test + 3 subtests 3 tests
    Si uno falla Continúa con los demás Continúa con los demás
    Identifica el caso que falla Sí Sí
    Muestra los casos correctos individualmente Normalmente no Sí con -v
    Salida fácil de interpretar Menos Más

    En ese sentido esta es una de las ventajas de pytest: al trabajar con datasets, se ve más claramente qué casos pasan y cuáles fallan.
