    Introducción a Python - Linters

    1. Introducción

    Hay determinados problemas en el código que pueden detectarse antes de ejecutar el programa:

    • errores de sintaxis;
    • nombres que no existen;
    • módulos importados pero no utilizados;
    • variables creadas pero no usadas;
    • código poco legible o difícil de mantener;
    • uso de malas prácticas;
    • estilos de código inconsistentes.

    Las herramientas que analizan el código buscando este tipo de problemas se denominan linters. En Python existen distintas herramientas, entre ellas:

    • Flake8
    • Pylint
    • Pyflakes
    • Ruff
    • ...

    En este tema utilizaremos principalmente Flake8. Flake8 reúne comprobaciones procedentes de herramientas como:

    • Pyflakes, para detectar determinados errores en el código;
    • pycodestyle, para comprobar convenciones de estilo;
    • McCabe, para medir complejidad ciclomática.

    Entre otras cosas puede detectar imports no utilizados, nombres no definidos, problemas de espaciado, líneas demasiado largas y funciones excesivamente complejas.

    ¿Qué hace un linter?

    Un linter realiza análisis estático del código: examina el código fuente sin necesidad de ejecutarlo.

    Un linter puede detectar muchos problemas, pero no puede garantizar que el programa funcione correctamente. Para comprobar el comportamiento del programa necesitamos técnicas como el testing.

    1.1. Linter, formatter y testing

    Conviene distinguir tres tipos de herramientas:

    Herramienta Objetivo
    Linter Detectar problemas, malas prácticas y errores de estilo
    Formatter Modificar automáticamente el formato del código
    Testing Comprobar que el programa produce los resultados esperados

    Por ejemplo:

    • flake8 es principalmente un linter;
    • black es un formatter;
    • pytest permite realizar tests.

    Estas herramientas se complementan entre sí.

    A continuación:

    1. se aprte de un fichero con errores: test_linters_inicial.py;
    2. se crea un entorno virtual;
    3. y se instala flake8;
    4. se prueba el linter desde la línea de comandos;
    5. y se utiliza integrado con el editor Visual Studio Code;

    2. Instalación

    2.1. Entorno virtual

    • Crear y activar
    calidad$ python -m venv venv
calidad$ source venv/bin/activate 
(venv) calidad$
    • Instalar flake8
    (venv) @tos:~/calidad$ pip install flake8

    Muchos avisos de un linter no provocan necesariamente un error durante la ejecución.

    Una variable no utilizada, por ejemplo, no impide que el programa funcione, pero puede indicar código innecesario o un olvido del programador.

    Hay también avisos de estilo: líneas de más de 79 caracteres, demasiados espacios después de un operador, etc.

    4. Algunos códigos habituales

    No corregir sin pensar

    Un linter señala problemas, pero normalmente es el programador quien decide cómo corregirlos.El objetivo no es conseguir que desaparezcan todos los mensajes a cualquier precio.

    Hay que comprender qué está señalando cada aviso y decidir cuál es la corrección adecuada.

    • F401 - Import no utilizado
    import os

    Si posteriormente no se utiliza os muestra F401 'os' imported but unused

    • F841 - Variable local asignada pero no utilizada
    def ejemplo():
    resultado = 10
    print("Fin")

    Si resultado nunca se utiliza muestra F841 local variable 'resultado' is assigned to but never used ```

    • E225 - Falta espacio alrededor de un operador

    No recomendado:

    total=precio*cantidad

    Recomendado:

    total = precio * cantidad
    • E501 - Línea demasiado larga

    Podemos dividir expresiones largas utilizando paréntesis:

    mensaje = (
    "Este texto se ha dividido "
    "en varias líneas del código."
)

    Analizar un directorio completo

    Puede analizar el directorio actual:

    flake8 .

    O una carpeta concreta:

    flake8 src/

    5. Usando el linter en el editor

    Visual Studio Code dispone actualmente de una extensión Flake8 publicada por Microsoft. Una vez instalada:

    • los problemas aparecen directamente en el editor;
    • también aparecen en el panel Problemas;
    • el análisis puede ejecutarse automáticamente al trabajar con archivos Python.

    Configuración antigua de VS Code

    En versiones antiguas se elegía el linter mediante Python: Select Linter que debái estar previamente instalado.

    Ese procedimiento está obsoleto. La extensión actual incluye su propia versión de Flake8, aunque también puede configurarse para usar una instalación del entorno del proyecto.

    Para este curso es suficiente recordar:

    1. instalar Flake8 en el entorno virtual para usarlo desde terminal;
    2. instalar la extensión Flake8 de Microsoft para usarlo desde VS Code.

    6. Seleccionar reglas

    Podemos revisar solo determinados códigos: use --select y se le indican los códigos a comprobar:

    flake8 --select E225,E501 test_linters_inicial.py

    También puede seleccionar grupos:

    flake8 --select E,W .

    7. Ignorar reglas

    De forma similar, puede ignorar códigos con la opción --ignore : 

    flake8 --ignore E501,E303 test_linters_inicial.py

    8. Ignorar una línea

    Es posible ignorar un aviso en una línea concreta:

    import modulo_no_usado  # noqa

    noqa no sustituye a corregir el código

    Debe utilizarse solo cuando exista una razón clara para mantener esa línea.

    9. Configuración en fichero

    Tiene por otra parte la posibilidad de crear un fichero de configuración. Flake8 admite configuración en:

    • .flake8
    • setup.cfg
    • tox.ini

    La configuración se coloca en una sección:

    [flake8]

    Un posible fichero tox.ini en la raiz del proyecto podría ser:

    tox.ini
    [flake8]
ignore = E501,E303
exclude = .git,__pycache__,old,build,dist
max-line-length = 100
max-complexity = 10

    Después basta ejecutar:

    flake8 .

    De forma simplificada, la prioridad de la configuración es:

    1. las opciones de línea de comandos tienen prioridad;
    2. después se usa la configuración del proyecto;
    3. finalmente se aplican los valores por defecto.

    10. Ejercicio

    Utilizar la herramienta flake8 con el código de los ejemplos y ejercicios de clase. Revisar y corregir los errores que muestra.
